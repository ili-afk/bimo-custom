# Что учить, чтобы сделать BIMO Custom

Короткий ответ: **Python. Один язык. Больше ничего не нужно.**

Остальное — не «языки», а мелочи вокруг: немного bash, JSON и понимание, как работает звук.

## 1. Почему именно Python

Я залез в исходник оригинала. Вот факты, а не рассуждения:

| Факт | Значение |
|---|---|
| Язык репозитория (GitHub) | **Python** |
| Весь агент | **один файл `agent.py`, 1081 строка** |
| Зависимости | 8 штук, все питоновские |
| Компилируемый код | **нет вообще** |

То есть весь робот — это один питоновский файл. Не C++, не Rust, не «сложный стек». Ты его прочитаешь целиком за вечер, если знаешь Python.

### Что именно тянет `agent.py`

```
sounddevice      — слушать микрофон и играть звук
numpy            — массивы чисел (звук — это массив чисел)
scipy            — фильтры (обрезать шум, склеить куски)
```

Плюс `tkinter` — он встроен в Python, отдельно ставить не надо. На нём сделано окно с лицом.

**Вывод:** учить надо не «языки», а **Python + эти 8 библиотек**. Причём библиотеки — по мере надобности, а не все сразу.

## 2. Что конкретно знать в Python

Не «весь Python», а рабочий минимум под этот проект. По возрастанию:

### Уровень 1 — без этого не прочитать код (1–2 недели)
- переменные, строки, f-строки, числа
- списки, словари, кортежи — **словари важнее всего**, конфиг и состояние агента живут в них
- `if / for / while`, `try / except` (в агенте полно обработки ошибок — микрофон отваливается регулярно)
- функции, аргументы по умолчанию, `*args`
- модули и импорты, `pip install`
- работа с файлами и путями (`pathlib`, `open`), `json.load` / `json.dump`
- виртуальное окружение: `python -m venv venv`

### Уровень 2 — без этого не понять архитектуру (1–2 недели)
- **классы** — в оригинале есть класс агента, состояние, методы
- **`threading`** — критично. Агент одновременно слушает микрофон, думает и рисует лицо. Это три потока
- **`queue`** — как потоки передают друг другу данные, не мешаясь
- **`subprocess`** — запуск внешних программ (пригодится для управления ПК)
- **`atexit`, `signal`** — корректно выключиться
- генераторы, `with`, декораторы (понимать, не писать свои)

### Уровень 3 — под мои фичи (по ходу)
- `asyncio` — когда пойдёт облако и стриминг ответов
- `requests` / `httpx` — запросы к облачной модели
- `tkinter` + `Pillow` — лицо и анимация
- `logging` — чтобы видеть, почему сломалось

## 4. План на 4 недели (по 1–1.5 часа в день)

Каждую неделю — не «глава учебника», а **кусок BIMO**. Так не бросишь.

### Неделя 1 — база Python
- Синтаксис, списки/словари, функции, файлы, JSON.
- **Задача недели:** скрипт, который читает `config.json` и печатает настройки. Потом — сохраняет изменённые обратно.
- Проверка: понимаешь каждую строку.

### Неделя 2 — звук
- `sounddevice`: записать 3 секунды с микрофона в `.wav`. Потом проиграть.
- `numpy`: понять, что звук — это массив чисел от -1 до 1.
- **Задача недели:** записываешь голос, сохраняешь файл, играешь обратно. Уже половина «уха» агента.

### Неделя 3 — потоки и состояние
- `threading` + `queue`.
- **Задача недели:** два потока — один каждые полсекунды пишет время в очередь, второй его печатает. Останавливается по `Ctrl+C` без ошибок.
- Это ровно та схема, на которой держится весь агент.

### Неделя 4 — лицо
- `tkinter`: окно, круг, текст. `Pillow`: картинка.
- **Задача недели:** окно, которое по нажатию клавиши меняет выражение лица: `idle → listening → thinking → speaking`.
- Это буквально `faces/` из оригинала, только твоими руками.

**После этих 4 недель** ты читаешь `agent.py` и понимаешь его целиком. Дальше — только добавлять.

## 5. Как читать `agent.py` (порядок, а не «сверху вниз»)

Не начинай с первой строки — утонешь в импортах и константах. Иди по кругу:

1. **Найди главный цикл** — `while` в конце файла. Пойми, что он крутит.
2. **Найди состояния** — там будут строки вроде `idle`, `listening`, `thinking`, `speaking`. Выпиши их на бумагу и нарисуй стрелки: из какого в какое можно перейти.
3. **Найди функцию, которая слушает микрофон** — и посмотри, как она решает «это кодовое слово или нет».
4. **Найди функцию, которая зовёт модель** — и посмотри, что она отправляет и что получает.
5. **Найди функцию, которая рисует лицо** — и посмотри, как она узнаёт текущее состояние.
6. Только теперь читай `config.json` и `setup.sh`.

После этого у тебя в голове будет схема, а не 1081 незнакомая строка.

## 6. Чему **не** учиться сейчас

- **C++ / Rust** — не нужно для этого проекта.
- **Алгоритмы и структуры данных «по книжке»** — вернёшься, когда упрёшься.
- **Docker / Kubernetes** — один Pi, один процесс. Не усложняй.
- **Веб-фреймворки** (Django, React) — пока лицо на `tkinter`, они не нужны.
- **Ещё три языка «на всякий случай»** — самая частая причина, почему проект не готов. Один язык, доведённый до рабочего состояния, лучше пяти начатых.
